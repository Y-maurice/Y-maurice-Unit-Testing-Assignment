A hidden input is anything a method depends on that is not passed to it: the clock, randomness, static state, the file system, the console, or a slow external call.

I searched `src/` with `Select-String` for `DateTime.Now`, `DateTime.Today`, `Random`, `Thread.Sleep`, `Task.Delay`, `File.`, `Path.`, `Directory.`, `Console.Write`, `Environment.`, `static` and `new X()`, and then opened every hit in its file.

## Evidence from my own runs

- **The seed data depends on the date.** I printed the booking list of the console on two different days. On Sunday 2026-11-08 `DN-SEED-0001` cost 4,800.00 and `DN-SEED-0002` cost 12,700.00; on Monday 2026-11-09 the same seed bookings cost 5,100.00 and 11,900.00. Nothing in the code changed between the runs: the seed dates are relative to `DateTime.Today`, and the weekend surcharge (BR-31) counts Fridays and Saturdays, so a different weekday gives a different price (row 19).
- **The refactor keeps the behaviour.** After each step I built the solution, ran the 5 legacy tests (all pass) and compared the console output with the output of the previous commit taken on the same day. For the external services I also compared a scripted booking (a booking for customer 2) before and after each commit, with the random reference masked, because the menu listings never call these classes.
- **Final search.** I searched `src/` (without `ConsoleApp`) for `DateTime.Now`, `DateTime.Today`, `new Random`, `Thread.Sleep`, `static class` and `new` of every repository, gateway and sender. It now finds only: code comments, the two static pure helpers (`RentalMath`, `LoyaltyService`), and the internals of the real adapters (`PaymentGateway` and `SmsSender` keep their delays and random failure on purpose). No service creates a collaborator, reads the clock directly or uses static state.
- **Final test run.** `dotnet test`: 43 tests, 42 pass. The only failure is the `RentalMath` 1500-minute case from Task 1 (a bug candidate for Task 10), and all 11 architecture tests pass.

## Decision: the real adapters keep their behaviour

Task 4 says behaviour must not change, so the real `PaymentGateway`, `SmsSender`, `EmailSender` and `AuditLog` keep their delays, random failure, console output and files. What changed is that the services only see interfaces, so a test can use a double instead. The hidden inputs inside these adapters are therefore controlled from a test through the interface (rows 10 to 16).

## Considered, not removed

- `ReceiptFormatter` line 6 uses `Environment.NewLine`. It is the same on every run on one machine, so it is not a source of flaky tests. I may revisit it if line endings matter for the receipt snapshots.
- `RentalMath` and `LoyaltyService` are static but receive all their inputs as parameters, so they have no hidden input.
- The console reads its menu choices and values with `Console.ReadLine`. That is the user interface of the staff menu, not a hidden input of the business logic, and no test goes through it.
